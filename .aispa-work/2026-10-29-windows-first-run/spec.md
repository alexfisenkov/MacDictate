# Спецификация: понятный первый запуск Windows

## Задача
После скачивания и установки пользователь должен видеть, запущено ли приложение, что осталось настроить и как получить первую диктовку. Сейчас модель требует скрытого Save, модальные настройки отключают Alt, а состояние видно только в трее. Конфигурация компьютера друга неизвестна: эти причины подтверждены в коде, но не приписываются его устройству без проверки.

## Решение
Видимое основное окно и пошаговая готовность: модель → микрофон → горячая клавиша → первая диктовка. Один явный запуск настройки, затем автоматическая проверка зависимостей, сохранение загруженной модели и переход к следующему шагу. Пользователь не ищет английскую Save и значок в скрытом трее. Запись можно начать явной кнопкой; двойной левый Alt сохраняется.

| Метка | История | Приёмка |
|---|---|---|
| R01 | Получаю проверенное исправление первого запуска | Отчёт разделяет подтверждённые дефекты, гипотезы о друге и реальные проверки |
| R02 | Сразу понимаю, что скачать для Windows | Главная Windows-кнопка: установщик EXE, Windows10/11 x64; ZIP вторичен и объяснён; Mac не конкурирует одинаковым призывом |
| R02.1 | Знаю, что делать после загрузки | Страница/инсталлятор ведут: запустить EXE → завершить установку → открыть видимое окно MacDictate |
| R03 | Не жду несуществующего запроса разрешения | Окно объясняет desktop-переключатель Windows и даёт кнопку ms-settings:privacy-microphone; приложение не обещает UWP prompt |
| R03.1 | Проверяю свой микрофон | Список входных устройств, выбранное устройство, короткая реальная запись и индикатор сигнала; отсутствие устройства/ошибка/тишина имеют разные понятные объяснения, без ложного «доступ разрешён» |
| R03.2 | После настроек могу продолжить | Возврат в приложение позволяет повторить проверку; не меняем registry/group policy и не отключаем защиту Windows |
| R04 | Alt имеет видимый результат | Экран проверки двойного левого Alt показывает полученные нажатия/срабатывание; AltGr/сочетания/инжектированные события не запускают запись; ошибка регистрации видна |
| R04.1 | Alt не зависит от тяжёлого UI | Hook имеет отдельный message-loop поток; callback не выполняет запись/распознавание; восстановление после смены режима/выхода безопасно |
| R04.2 | Могу диктовать без Alt | Крупная кнопка «Начать запись»/«Остановить и распознать», Cancel, состояние и длительность видимы; тест клавиши не поглощается модальным setup guard |
| R05 | Понимаю шаги внутри программы | Русские и английские тексты, ясная последовательность, где говорить, как остановить, где появится текст, как найти программу в трее и повторно открыть окно |
| R06 | Подготовка не требует скрытого сохранения | После успешного verified download путь модели сразу атомарно сохраняется и готовность обновляется; прогресс/объём, отмена, повтор, ручная модель сохраняются |
| R06.1 | Понимаю, почему запись ещё недоступна | Готовность отдельно показывает runtime/model/microphone/hotkey; явное действие исправляет каждую причину; не объявлять микрофон рабочим без получения сигнала |
| R07 | Получаю первую расшифровку, а не только сборку | Guided trial проходит запись → bounded реальный Whisper → видимый текст/Copy; глобальный запуск сохраняет безопасный ввод в исходное поле, при отказе текст виден в основном окне |
| R07.1 | Видно, что идёт распознавание | Видимый busy/cancel/ошибка, без обещания мгновенной CPU-скорости; пустой результат не считается успехом |
| R07.2 | Исправление проверено до распространения | Локальные core/build проверки, независимый review, один финальный Windows CI с fresh-profile UI acceptance и реальным ASR/installed-copy. Synthetic mic/test injection отдельно маркируется; physical Win10/11 proof не подменяется Server2025 |
| R08i | Настройки переживают перезапуск | Старые settings.json читаются; выбранный микрофон/model/language сохраняются; модель не скачивается снова без нужды; только user-start setup запускает большую загрузку/проверку записи |
| R09i | Ошибки имеют следующий шаг | Нет сети, неверный hash, занятый/отключённый/тихий микрофон, missing runtime/model, отмена и ошибка ввода: понятный текст и доступное действие; исходные модели/аудиофайлы пользователя не удаляются |
| R10i | Программа заметна | Первый запуск и обычный Start Menu launch показывают окно; закрытие в трей объяснено, повторный запуск поднимает окно текущего экземпляра; запись/обработка видны поверх рабочего окна без захвата фокуса |

## Решения по реализации
- Сохраняем .NET10/WinForms/WinMM/локальный whisper.cpp, без новых runtime NuGet-зависимостей, облачного ASR, аккаунтов и лицензирования.
- Понятные RU/EN строки и DPI-friendly native controls; контролируемый layout-stress125/150% и bounds/PNG проверка, содержимое не обрезает основной шаг; фактический DPI монитора записывается отдельно. D01: hosted desktop не позволяет подтвердить физические мониторы125/150%, поэтому synthetic scale не выдаётся за native DPI.
- Никакого скрытого изменения разрешений Windows. Реальный mic test получает PCM, считает уровень; недостаточный сигнал объясняет возможный mute/не тот вход, а не объявляет конкретную аппаратную неисправность.
- Отдельный keyboard thread/message pump; события только метаданных, без keylogging. Тест Alt и обычная запись разделены состоянием интерфейса.
- Домашняя кнопка записи показывает результат в приложении; не вводим текст в собственное окно. Глобальный запуск использует существующую FocusIdentity и fail-closed fallback.
- Сохраняем существующие локальные данные и пользовательские модели. Прежняя модель с отличающимся hash не заменяется молча.
- Synthetic acceptance seams включаются только явным тестовым CLI, изолированный временный профиль, никогда не подделывают нормальную готовность микрофона. Реальный installed app остаётся обычным режимом.
- Исправление Windows выпускается отдельно от неизменённого macOS: версия Windows1.6.1, make_latest=false, прямой Windows download pin. Глобальный latestMac1.6.0 и updater не получают ложного Mac update. Release ledger и latest-windows.json согласуются.

## Границы
См. interfaces.md. Один исполнитель приложения, затем один исполнитель доставки/сайта/приёмки. Оценка 3–4тыс. изменённых строк с тестами, T1.

## Вне рамок
Не добавляем AI-редактор, GPU/ARM-порт, учётные записи, оплату, удалённый доступ к компьютеру друга, покупку сертификата. Существующие ограничения подписи раскрываются, но unsigned-пакет не называется signed. Это не отменяет ни одного требования брифа.

## Открытые внешние проверки
Доступа к физической Windows друга сейчас нет. Автоматические проверки обязаны честно назвать источник PCM/клавиш и ОС; фактический mic/Alt/editor тест клиента остаётся отдельной строкой приёмки, до него не писать «проверено на компьютере друга». Полезный безопасный диагностический отчёт содержит только версии, статусы и коды ошибок; никогда аудио/расшифровку, имена приложений или устройства пользователя без необходимости.
